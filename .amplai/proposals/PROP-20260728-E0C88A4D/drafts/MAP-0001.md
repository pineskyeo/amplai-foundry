# AMPLAI Knowledge Map

## Concepts

- [[Harness는 Agent 실행을 통제하는 운영 껍질이다]]
- [[Loop는 목표 달성까지 반복하는 제어 흐름이다]]
- [[Meta-loop는 trigger 기반 replay와 review를 거치는 제한된 개선 흐름이다]]
- [[Context는 실행 입력이고 Memory는 재사용 가능한 보존 정보다]]
- [[Canonical Knowledge는 검토된 공식 지식이다]]
- [[Memory Candidate는 불변 Source 근거와 비교 가능한 의미 구조를 가진 제안이다]]
- [[Semantic Anchor는 여러 Source 표현을 하나의 검토 가능한 의미 identity로 연결한다]]

## Governance

- [[입력은 느슨하게 받고 내부 지식은 엄격하게 관리한다]]
- [[공식 지식 후보와 주장은 불변 Source의 확인 가능한 근거를 가져야 한다]]
- [[LLM은 Canonical Knowledge를 직접 변경하지 않고 Proposal과 검토를 거친다]]
- [[검색 인덱스는 공식 원본에서 재생성 가능해야 한다]]
- [[Semantic identity 비교는 knowledge kind 선택과 canonical 생성보다 먼저 수행한다]]
- [[UNCERTAIN semantic comparison은 Canonical CREATE나 UPDATE를 승인하지 않는다]]

## Compiler And Evaluation

- [[Knowledge Representation Pipeline은 저장·검색·문맥 표현을 분리한다]]
- [[Governed Knowledge Compiler는 Source부터 Canonical Renderer까지의 통제 경계를 분리한다]]
- [[Semantic Identity & Comparison Kernel은 Candidate와 Proposal 사이의 비교 경계를 제공한다]]
- [[Knowledge Steward Golden Set은 semantic comparison과 governed routing을 평가한다]]
- [[Candidate의 의미 identity, 중복과 충돌은 어떻게 판정하는가]]
- [[Knowledge Intake의 초기 자동 승인 경계는 어디까지인가]]
- [[Scope 모델의 최소 공식 field는 무엇인가]]

## Roadmap Candidates

- [[Phase 1B의 첫 신규 구현 slice는 Phase 1A gate 뒤 Semantic Comparison 계약을 고정한다]]
