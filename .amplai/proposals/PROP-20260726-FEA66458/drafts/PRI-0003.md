# LLM은 Canonical Knowledge를 직접 변경하지 않고 Proposal과 검토를 거친다

## Principle

LLM은 candidate와 관계를 제안하는 해석기이며 Canonical Knowledge를 직접 쓰거나 수정할 권한을 갖지 않는다. canonical identity, path, schema validation, relation validation과 rendering은 deterministic system이 담당한다.

변경 proposal은 근거, 영향 대상과 lifecycle 변화를 명시하고 review를 거친다. Decision, architecture boundary, ontology, policy, 권한과 production 관련 변경처럼 고영향 의미 변경은 Governor가 요구하는 명시적 승인을 거친다. 분류 불일치나 근거 부족은 자동으로 Decision을 확정하지 않고 review 또는 question으로 남긴다.
