# Project Memory의 Source of Truth와 Source Store 경계는 어디까지인가

## Question

Project가 Memory를 소유한다는 원칙이 모든 업무 데이터의 단일 물리 원본을 뜻하는가? 현재 reviewed knowledge의 canonical source는 Markdown과 Git이지만 Jira issue, Git commit과 session state는 각 운영 system이 authoritative source일 수 있다.

Source 원문과 canonical asset을 같은 repository의 다른 경로에 둘 수 있는 범위는 어디까지인가? 대용량 원문, 보안 등급, 개인정보, 사내 문서와 binary artifact 때문에 별도 Source Store가 필요해지는 조건을 정의해야 한다.

## Decision Needed

Project Memory를 통합 조회와 governance 경계로 정의할지, 모든 데이터의 단일 저장소로 정의할지 구분해야 한다. 각 데이터 유형의 authoritative source, retention, access policy와 derived projection을 명시해야 한다.
