## 로컬 체크아웃이 remote 와 다르다 — 함정

`kit_distribute.py --verify` 는 **이 호스트의 로컬 체크아웃**을 본다. remote 가 아니다.

```text
                 로컬 브랜치                        dirty  main대비    kit
amplai-foundry   main                                  0   일치       2.3.1
synapse          feat/chuck-max-temperature-rename    27   68 뒤      2.3.0 (미commit 설치)
cortex           feat/card-id-and-prober-id            2  192 뒤      없음
```

그래서 `--verify` 는 synapse·cortex 를 mismatch 로 보고한다. **배포가 덜 된 게 아니라 로컬이
main 을 안 받은 것이다.** remote `main` 셋은 전부 2.3.1 이다.

사용자가 cortex 를 Store 에 묶으려다 dirty gate 에 막힌 상태에서 이 세션이 끝났다.
**재설치가 아니라 main 을 받는 것이 먼저다.**

```bash
cd ~/workspace/cortex
git log --oneline origin/main..HEAD    # 앞선 1 commit 이 살아 있는 작업인지 먼저 본다
git checkout main && git pull origin main
```

두 저장소의 로컬 작업 사본은 이 세션이 **건드리지 않았다.** cortex·synapse 작업은
`origin/main` 에서 뜬 별도 worktree 에서 했고 끝나고 지웠다.

## cortex 는 설치됐지만 아직 조용하다

cortex 는 이번이 **첫 설치**다(이전엔 kit 이 아예 없었다). 그런데 Store 에 묶여 있지 않다.

```text
.ai-team/app.json              있다.  app_id=cortex, project_id=ai-platform
.ai-team/local/project.json    없다
app.json 의 project_home_hint  없다
```

`discover_project_home()` 은 `AMPLAI_PROJECT_HOME` → `local/project.json` → `app.json` 의
hint 순으로 찾고, **셋 다 없으면 hook 이 조용히 아무것도 안 한다**(설계된 휴지 상태).
즉 cortex 에서 세션을 열어도 상태 주입이 안 뜬다. 묶으려면 둘 중 하나다.

```bash
export AMPLAI_PROJECT_HOME=~/workspace/amplai-project        # 그 세션에서만
# 또는 (main 을 받은 뒤, tree 를 정리하고)
.venv/bin/python scripts/kit_distribute.py --all --app cortex \
  --project-home ~/workspace/amplai-project
```

**`--project-home` 을 임시 경로에서 실행하지 마라.** Store 의 `cortex` repo_path 가 그
경로로 덮인다. 이 세션이 한 번 겪고 되돌렸다 — 복구 절차는
`specs/008-cortex-redeploy/spec.md` 의 "실험이 실제 Store 를 건드렸고 되돌렸다" 절에 있다.
