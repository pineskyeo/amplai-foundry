Portable Development Guide

Scope

AMPLAI Loop Kit 2.5.0 is a local integration candidate. Installation, a passing local check, and a rendered guide do not publish a release or approve a server deployment. The existing repository rules and Project Store remain authoritative.

Start A Work

Use the existing work entry point in the app repository: Claude Code /work or Codex $work. The controller reads the assigned Work, contract, source evidence and repository rules before changing files. Design-only requests use design. A WAITING Work needs its actual upstream result; a chat message saying DONE does not release a dependency.

Governing inputs are the explicitly configured repository instructions and applicable active Decisions. They are not release guides: a missing guide review must not erase the rules needed to perform that review. The generic baseline requires AGENTS.md, its workflow and verifier registry. An app adds only its own approved instruction and Decision-ledger paths through the documentation policy's governing_inputs list. Security and retired-instruction metadata still apply. A historical Decision ledger is not selected wholesale; only active indexed Decisions and their typed evidence references enter the Context Pack. Validation reconstructs the complete expected set, so deleting an input and recalculating the pack's hash does not make it valid.

Owning release guides also need an active source entry in the repository knowledge map. Document selection alone does not register that entry. Foundry registers its three Kit guides at ordinary high priority; existing release, review and security filters still decide eligibility. Its guide check inspects both generated and stored Context records, their exact current source hashes and normal Context validation. Guide registration does not replace mandatory instructions or import unrelated product knowledge.

The generated handoff is a view. A terminal Work shows its own result and references, without asking another developer to claim or restart it. A lease expiry retains the existing retry delay. Heartbeat output hides the credential while renewal still uses the same private environment credential.

Install Safely

Start with the package's dry run in a disposable or approved target. The baseline is opt-in; existing rules, host trust, local modifications and Store bindings are preserved. A conflict requires reconciliation, not an automatic overwrite. Full package checksums must pass even when a version label is unchanged.

A borrowed baseline file keeps its existing local permissions across repeat installs, package updates and uninstall. Package permission changes apply only to installer-owned files. Local permission drift still requires explicit reconciliation; accepting that drift does not grant permission to replace borrowed content.

python3 tools/amplai-loop-kit/seal.py --verify
python3 tools/amplai-loop-kit/install.py --target /path/to/app \
  --app-id app-id --project-id project-id \
  --bootstrap-baseline --repo-profile generic --dry-run

Review the reported changes before an explicitly authorized install. Omit Project Store registration and auto-start unless they are separately in scope. For interrupted installs, inspect the existing recovery journal and verified backup. Do not erase the backup to make a retry pass.

Keep Code And Documents Together

The normal Work discovers affected guides, updates their owning source, records a content-bound review, and builds configured offline views before independent review. No separate user request to update documents is required.

Current guides use one metadata owner: JSON frontmatter or one adjacent .amplai.json sidecar. Explicit source roots may identify individual Markdown files. Enrol a legacy guide only after reading its ownership, audience, release and security scope; an old ACTIVE label is not verification. Preserve original text and history when adopting a sidecar.

Configured development-source routes bind template and instruction bytes to a current owning guide. They do not grant those files canonical guide status. Historical routes retain the exact prior revision; changed history requires a preservation review. Mandatory guide rules, unknown metadata and inaccessible dependencies still block completion. Non-required folder hints exclude generated Work records from their recursive inputs, so a review report cannot depend on itself. Structural directories likewise exclude the configured review result and its temporary publication stage; each review is verified separately. Explicit file references and other required directory members still bind their exact bytes and membership, including ignored inputs. The evaluator's three standard result files retain their evidence role. Other files in that directory still affect the candidate; the directory is not a blanket exclusion.

python3 scripts/loopctl.py docs impact specs/feature
python3 scripts/loopctl.py docs review-batch specs/feature --input /path/to/review.json
python3 scripts/loopctl.py docs sync-views specs/feature
python3 scripts/loopctl.py docs validate specs/feature

Review evidence binds the current source, dependencies, candidate and method. A code, document, policy, ontology pin or evidence change invalidates the previous review. An empty offline-view configuration is NOT_CONFIGURED, not an HTML verification result.

Review history is retained, not automatically pruned. Publication checks the exact serialized UTF-8 size before staging or replacing a file. The review store has an 8 MiB reader limit; an impact projection uses the configured max_file_bytes limit. If a result exceeds its limit, the operation fails and leaves the previous readable file and its permissions intact. Use concise attributed review reasons and rerun the failed operation after resolving the input size. Do not delete history to bypass a limit.

Atomic review and impact publication retains the existing POSIX owner, group and mode, even under a restrictive umask. A new record starts with readable private mode 0600. If permissions, identity, metadata or bytes change before the final publication check, the operation stops without replacing that changed file. Reinspect the current inputs before retrying. This local guarantee does not certify target ACLs, SELinux labels or extended attributes; verify those in the separately approved server environment.

Select And Share A Version

Offline HTML is derived from reviewed owner sources and an exact verified release set. It works without a network or JavaScript. Generated-only edits fail validation. Current and historical release IDs are explicit; latest cannot mean an arbitrary commit. User, developer, operator and executive views retain different content needs.

Keep internal guides inside the approved internal boundary. External HTML generation uses a separate finite approved input and digest, not a checkout with private sections hidden. Rendering does not approve publication, artifact activation or a new authentication system.

All document consumers check local references before relevance scoring or title/snippet output, for current and historical selection. The bounded full-document scanner covers whitespace, multiline definitions and HTML attributes, nested labels and balanced or escaped destination parentheses. Literal examples are checked too. Ambiguous syntax or scanner limits stop selection; this is not a promise to render every CommonMark feature.

The same check covers required inline-code and tree references, directory/glob members, and optional local targets that actually exist. Ignore or known-absent hints do not grant visibility to existing files. Both an alias and its resolved target constrain security. Escaping, dangling or cyclic aliases and resolution failures are not absent examples. Reject them before optional fallback, including parent aliases. Concrete path prefixes share the finite traversal budget. Ordinary absent examples and valid internal aliases retain their existing behavior; no outside content is read. Unknown targets fail closed. Dependency and visibility traversal have finite work budgets; code/tree references do not become hyperlinks or additional release pages.

The exact bare optional inline-code literals /work, /design, /hooks and /tmp denote existing command or standard-location notation, not implicit file dependencies. Required declarations, links, tree entries, decorated values and child paths do not use this exception. It is not a path-prefix allowlist or permission to read outside the repo.

HTML uses a finite reference subset. Single destinations such as href, src, poster, data, action and xlink:href use the same path/security check, including namespace tags. Compound URL lists/srcset, CSS/SVG functional references, srcdoc, refresh, base modifiers, active embedded languages and unknown value-bearing attributes are unsupported and stop the operation with UNSUPPORTED_PARSER. Inert attributes and data-/aria- metadata remain author text. Encode unsupported markup as descriptive text; the tool is not a browser parser or arbitrary prose DLP. Escaping at the renderer remains an additional safeguard.

Only HTTP/HTTPS with explicit authority, protocol-relative URLs and mailto are accepted as non-local URIs. Local file, executable/data and unknown schemes stop without exposing or reading the destination. All references remain subject to authored security review. The scanner and typed extractor charge retained prefixes/labels/paths before allocation, with an input-proportional budget and a 10,000-reference limit. Long repetitive lines can return SCOPE_INCOMPLETE even below the document byte limit; split the source meaningfully and review it again. A limit never produces an empty-success result or partial review. Declaration classification also charges its input before scanning. Header and separator checks avoid repeated suffix backtracking, including short near-matching declarations.

Impact candidate discovery applies the existing Work-memory role before parsing retained reports. Its bounded lean scan omits repeated declaration context and conservatively includes inline-code local names. This is candidate discovery, not required-dependency proof: current-guide and public-source validation retain full context and limits. Vault sources and unknown document roles are not excluded by this optimization. Unknown authority-bearing origin URIs can remain unavailable external candidates without being fetched or approved. They remain unsupported in exact dependency and visibility validation; a candidate result is not permission to publish an origin or its source.

URI escapes are interpreted once. Query and fragment delimiters are separated before decoding the path, so an encoded hash or a trailing semicolon remains part of the actual filename. URI targets are literal paths, not prose globs or editor locators. Unknown or higher-security targets stop selection without disclosing the target. A visible same-security historical reference does not make that target current. HTML additionally requires each local document link to belong to its exact approved bundle; raw HTML is escaped, not executed.

Preserve And Recover

Incremental gardening runs after review and is report-only. User backups, tracked documents, ADRs and incident lessons are not deleted because they are old, untracked or in Git history. A full scan requires its own explicit high-risk repository_gardening Work.

python3 scripts/loopctl.py garden incremental specs/feature
python3 scripts/loopctl.py garden full specs/gardening-work --report-only
python3 scripts/loopctl.py docs preserve --input /path/to/preservation-request.json
python3 scripts/loopctl.py docs plan-retirement --input /path/to/retirement-request.json

Preservation compares every original section byte with the retained source or an exact attributed destination. A summary cannot replace a unique invariant or incident lesson. Retirement planning is read-only. No destructive CLI or new approval authority is provided. Approved recovery fixtures verify source bytes, permissions, index, backup and failure boundaries; real repository retirement remains separately gated.

Verify And Hand Off

Run the selected slice through the existing evaluator, then the repository's full verifier. Record command, exit code, source hashes and environment. Independent review and current document evidence precede completion. Keep unverified host and server checks visible. This local macOS validation is not Python 3.6 execution or a RHEL7 deployment test.
