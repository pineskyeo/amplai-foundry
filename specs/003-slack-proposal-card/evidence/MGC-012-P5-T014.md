# MGC-012-P5-T014 — Pin the migration history and store identity guards

대상: round 11 `R-9` (Blocking-P2). 결정: `D-038`.

**실제 동작 결함이 아니다.** 두 guard 는 오늘 맞게 동작한다. 없는 것은 그 정확성을 붙잡는
test 다. round 11 mutation 이 둘 다에서 살아남았다.

## What Was Unprotected

| 대상 | 하는 일 | 잃으면 |
|---|---|---|
| `migrations.py` `_verify_rows` 의 연속성 검사 | 적용된 version 이 1부터 빈틈없이 이어지는지 본다 | migration 하나가 빠진 store 가 정상으로 열린다. 없는 table 이나 없는 제약 위에 governed 판단이 쌓인다 |
| `verify_schema` 의 `store_kind` metadata 검사 | 이 파일이 governance store 인지 확인한다 | 아무 SQLite 파일이나 governance store 로 열린다 |

`src/` 는 수정하지 않았다.

## Isolating The Right Branch (AC-04)

연속성 검사 위에 **미지원 future version 분기가 먼저 있다**. 빈틈을 잘못 만들면 그쪽이 먼저
잡아서 겨냥한 guard 를 고정한 것이 아니게 된다.

- 끝 version 을 지우면 → 그냥 낮은 version 이라 연속성이 유지된다. 아무것도 안 잡힌다
- 큰 version 을 넣으면 → 위의 미지원 분기가 먼저 잡는다
- **중간 version(5)을 지우면** → 모든 version 이 known 이라 위 분기를 통과하고 연속성 분기가 잡는다

test 가 세 message 중 어느 것이 나왔는지까지 확인한다.

```python
assert "연속적이지 않습니다" in message
assert "지원하지 않는" not in message
assert "현재 contract와 다릅니다" not in message
```
