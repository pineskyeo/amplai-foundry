# MGC-012-P5-T010 — Let a transient store failure spend its retry budget

대상: round 11 `R-2` (P1). 결정: `D-038` 항목 1~3, 승인 기록 `D-038`.

## The Defect

`REVIEW_CARD_PREPARE_FAILED` 는 `OutboxReconcileError` 라 `unreconcilable=True` 로 즉시 dead
letter + operator hold 였다. 재시도 예산을 한 번도 쓰지 않았다. sqlite lock 한 번에 destination
전체가 영구 정지했고, 그 hold 는 schema 가 append-only 라 되돌릴 수 없다.

**같은 저장소가 스스로 반대로 적어놨다.** `ingress_worker.py:228-259` 는 같은
`sqlite3.OperationalError` 를 `RETRY` 로 분류하고 그 test 이름이
`test_a_transient_sqlite_error_retries_instead_of_holding` 이다. 한 저장소에서 같은 예외가 두
정책을 받았다.

## What Changed

**정책을 새로 만들지 않았다.** `ingress_worker` 가 이미 쓰던 것을 공유 위치로 올렸다.

- `store.py` 에 `is_store_corruption` 과 `is_transient_store_failure` 를 두었다.
  `store.py` 는 `filesystem` 과 `migrations` 만 import 하므로 순환이 없고,
  `GovernanceStoreError` 를 정의하는 자리라 의미도 맞는다.
- `ingress_worker` 의 `_is_corruption` 사본을 지우고 공유 helper 를 쓴다. **ingress 동작은
  바뀌지 않았다.**
- `events.py` 에 `OutboxRetryableError` 를 `GovernanceEventError` 형제로 추가하고
  `deliver_next` 에 분기를 더했다 — `unreconcilable=False` 로 `fail()` 을 부르되
  `error_code=error.code` 를 넘긴다.
- `slack_projection` 의 준비 경로가 일시적 store 실패를 `OutboxRetryableError`
  (`REVIEW_CARD_PREPARE_UNAVAILABLE`) 로 올린다. 손상과 그 외는 그대로
  `REVIEW_CARD_PREPARE_FAILED` 다.

분류는 `except` 블록 안에서 boolean 하나로 끝낸다. 예외 객체를 밖으로 들고 나가면 credential 을
든 frame 을 살려두게 되고, Python 이 블록을 벗어나며 예외 변수를 지우므로 뒤에서 다시 볼 수도
없다.

## Why Preserve The Cause Code

`deliver_next` 의 `except Exception` 도 재시도로 흐르지만 예외를 보지 않고
`OUTBOX_DELIVERY_FAILED` 를 박는다. round 11 `R-1` 이 정확히 그 형태를 결함으로 셌다 —
"수렴하기는 한다 (…) 그 값은 원인이 아니고". 같은 항의를 다시 받을 코드를 쓰지 않았다.

## What This Does NOT Fix

**되돌릴 수 없는 operator hold 는 남는다.** 예산을 써도 소진되면 같은 hold 에 도달한다
(`events.py` `fail()` 의 `exhausted or unreconcilable` → `_dead_letter`, 이 함수는 분기 없이
hold 를 insert 한다). 기본 설정에서 버는 시간은 5+10+20+40 = 75초다.

해제는 API 부재가 아니라 **schema 금지**다 — `migrations.py` 의
`CHECK (resolved_at IS NULL)` 과 append-only 트리거 둘. 여는 것은 migration 을 포함한 새
기능이고 `D-038` 항목 1 이 범위 밖으로 뺐다. `spec.md` Assumptions 에 기록했다.

## Scope Expanded During Implementation

`tests/test_review_cards.py` 는 처음 `allowed_paths` 에 없었다. 구현 중 그 파일의 test 두 건이
**T004 의 과잉 수정을 고정하고 있다**는 것을 확인했다 —
`test_ordinary_prepare_exception_dead_letters_instead_of_escaping` 이 "일시적 store 실패는 즉시
dead letter" 를 요구한다. `R-2` 를 고치면 반드시 실패한다.

조용히 넓히지 않고 manifest 의 `scope.include` 와 `allowed_paths` 에 이유와 함께 적고 넓혔다.
`T013` 이 같은 파일을 갖지만 `T013` 이 뒤라 순서 충돌은 없다.

**기대를 지우지 않고 옮겼다.**

| 이전 | 지금 |
|---|---|
| `..._dead_letters_instead_of_escaping` | `..._retries_instead_of_holding` — 재시도로 가고 destination 이 안 멈춘다 |
| (없음) | `..._still_dead_letters_once_the_budget_is_spent` — **소진되면 여전히 dead letter + hold** |
| (없음) | `..._corrupt_store_dead_letters_on_the_first_attempt` — 손상은 여전히 즉시 terminal |
| `..._raises_a_catchable_reconcile_error` | `..._raises_a_catchable_error_without_leaking_its_cause` (2 param) |

두 번째 줄이 중요하다. 재분류가 안전망을 없애지 않았음을 test 가 붙잡는다.
