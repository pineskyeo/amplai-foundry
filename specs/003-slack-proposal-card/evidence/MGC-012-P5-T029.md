## AC-01 / AC-02 — The Regression, Against HEAD

`GovernanceStore._configure` 를 `sqlite3.OperationalError("disk I/O error")` 로 바꾸고
`LegacyMigrationForwardRecoveryPlanner.plan()` 을 부른다.

```text
wave 8  : amplai_foundry.governance.store.GovernanceStoreError | Governance Store connection을 열 수 없습니다: disk I/O error
HEAD    : sqlite3.OperationalError | disk I/O error
```

**예외 class 가 바뀌었다.** `sqlite3.Error` 를 잡던 handler 는 더 이상 안 잡는다.

## AC-03 — The Nine Handlers

round 15 regression lens 가 AST 로 전수했다. `connect()` 를 감싸며 `sqlite3.Error` 를 잡되
`GovernanceStoreError` 나 `Exception` 은 안 잡는 `try` 다.

| 파일 | connect 위치 |
|---|---|
| `legacy_lifecycle.py` | 157 |
| `legacy_migration.py` | 823, 1069, 1114, 1169 |
| `legacy_recovery.py` | 206, 415 |
| `legacy_rollback.py` | 180, 549 |

**아홉이다.** reviewer 는 `legacy_recovery.py:206` 하나를 실행으로 재현했고 나머지 여덟은
정적 전수다. 같은 pattern·원인이다.

## The Change

```python
_OPEN_FAILURES: tuple[type[BaseException], ...] = (
    GovernanceFilesystemError,
    OSError,
)
```

`sqlite3.Error` 를 뺐다. `_raw_connection` 의 PRAGMA 를 감싼 try/except 도 되돌렸다.

**의도적으로 정규화하지 않는 것** — `_configure` 의 PRAGMA, `PRAGMA database_list`,
`_raw_connection` 의 PRAGMA 에서 나는 `sqlite3.Error`. 셋 다 HEAD 동작이고 아홉 handler 가
그것에 의존한다.

**유지하는 것** — `sqlite3.connect` 자체의 실패는 `_raw_connection` 이 예전부터
`GovernanceStoreError` 로 감쌌다. HEAD 부터 있던 것이라 그대로 둔다.

## What T024 Got Wrong

`T024` evidence 의 sibling census 는 **맞았다.** 일곱 형제를 정확히 셌다. 틀린 것은 그
전부를 덮기로 한 판단이다.

round 14 `P1-1` 이 요구한 것은 `GovernanceFilesystemError` 하나였다. 나머지는 "형제를 전수로
센다" 를 과하게 적용한 결과다.

**세는 일과 덮는 일은 다른 판단이다.** 이번 wave 가 배운 것 중 하나다. 형제를 다 세는 것은
옳고, 센 것을 다 바꾸는 것은 별개로 정당화해야 한다.

그리고 `T024` evidence 가 "호출자를 하나도 안 건드렸다" 를 장점으로 적었는데, 아홉 곳에서는
그것이 결함이었다 — 안 건드렸기 때문에 그들이 의존하던 예외 class 가 조용히 바뀌었다.
