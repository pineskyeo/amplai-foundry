## The Change

`decisions.py` module level 에 `clear_exception_frames` 하나를 두고 나머지 셋을 지웠다.

**여기 둔 이유는 import 방향이다.** 네 module 중 `decisions` 만이 나머지 셋의 (직접 또는 간접)
의존 대상이다.

```text
slack_cards      -> decisions            (직접)
slack_projection -> slack_cards          -> decisions
slack_http       -> slack_projection     -> ... -> decisions
review_cards     -> decisions            (직접)
```

반대 방향은 없다. `decisions` 는 `active_proposals`, `authority`, `events`, `legacy_gates`,
`models`, `store` 만 import 하고 그 넷 중 아무것도 안 쓴다. **순환이 생기지 않는다.**

**이름을 공개형으로 바꿨다.** `classify_interruption`, `raise_sanitized_interruption` 과 같은
성격의 module 간 helper 이고 그 둘도 공개형이다. `governance/__init__.py` 로는 export 하지
않았다 — 공개 API 표면을 넓힐 이유가 없다 (round 12 `C-1` 이 기록 없는 export 추가를 잡았다).

## Scope Expansion — `review_cards.py`

`review_cards.py:548` 이 `DecisionService._clear_exception_frames(error)` 로 class 를 가로질러
불렀다. manifest 의 `scope.include` 가 이미 지목한 그 호출이다. 정의를 module-level 로 옮기면
이 한 줄이 따라와야 하고, 남겨 두려면 `DecisionService` 에 위임 staticmethod 를 둬야 하는데
**그것이 바로 이 task 가 없애려는 사본**이다.

`allowed_paths` 에 `src/amplai_foundry/governance/review_cards.py` 를 더하고 manifest 에 사유를
적었다. 한 줄 호출 갱신만 했고 다른 변경은 없다. wave 5 `T010` 이 같은 방식으로 확장을
기록했다 — 조용히 넘어가지 않는다.
