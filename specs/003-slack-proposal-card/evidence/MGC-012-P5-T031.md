# MGC-012-P5-T031 — Make The Dead-Letter Loop Terminate And Guard Its Write

Wave 10. round 16 `S-1`(P0), `FR-1`(P1), `FR-2`(B-P2), `C16-1`(P1). `D-045`.

**넷이 한 구조에서 나왔다.** `T027` 이 round 15 의 P0 를 고치려고 `while True` +
transaction 밖 write 를 넣었는데, 그 구조가 요구하는 넷을 안 채웠다.

| 구조가 요구하는 것 | 빠진 결과 | 닫는 방법 |
|---|---|---|
| 진행 보장 | `S-1` 무한 루프 | 이미 치운 id 를 기억하고 두 번째 만나면 닫는다 |
| 경합 guard | `FR-1` 살아 있는 lease 삭제 | `claim_generation` + claim 가능 state 조건 |
| write 실패 처리 | `FR-2` D-045 가 거절한 상태 복귀 | `IngressError` 로 닫아 `CLAIM_FAILED` 가 되게 |
| 모름과 없음의 구분 | `C16-1` 거짓 음성 | `is_unreadable()` |

## The Change

**진행 보장.** 반복 상한 대신 **이미 치운 `command_id` 를 기억한다.** 상한은 손상이 많을 때
정상 진행을 자르지만, 이 조건은 진짜로 진행이 없을 때만 멈춘다.

**경합 guard.** `_UnreadableCommand` 가 `claim_generation` 을 함께 나르고, write 가
`WHERE command_id = ? AND claim_generation = ? AND state IN ('pending','retry_wait')` 를
건다. 조건이 안 맞아 0행이면 **그것이 옳은 결과다** — 다른 worker 가 가져간 것이다. 실패로
다루지 않고, 다만 loop 가 진행 없음을 판정할 수 있게 한다.

**write 실패.** `(GovernanceStoreError, sqlite3.Error)` 를 잡아
`IngressError(UNREADABLE_COMMAND)` 로 닫는다. `process_next` 가 `CLAIM_FAILED` 로
기록한다. **조용히 넘어가지 않는다.**

**모름과 없음.** `get()` 의 signature 는 안 바꿨다. 유일한 src caller 인
`committed_decision`(`ingress_worker.py:310`)은 `None` 을 "결정 없음" 으로 쓰는 것이
맞다 — `D-042` 의 보수적 침묵이다. 구분이 필요한 것은 operator 조회뿐이라 `is_unreadable()`
을 따로 뒀다.
