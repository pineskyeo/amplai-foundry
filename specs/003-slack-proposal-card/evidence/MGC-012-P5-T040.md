# MGC-012-P5-T040 — Stop the freeze from carrying what the freeze itself creates

대상: round 18 `N18-4`(B-P2), `A18-R1`, `A18-7`.

## `N18-4` 앞부분 — freeze 가 자기 변경을 담았다

round 18 target manifest 는 `evidence-trace.jsonl` 에 대해 그 파일이 **4줄이던 시점의
hash** 를 담았다. 실제로는 7줄이었다. wave 11 이 freeze 를 실행한 **뒤에**
`verify_pass`·`docs_resolved`·`review_target_frozen` 세 줄을 더 썼기 때문이다.

세 reviewer 가 전부 그 한 건의 불일치를 보고했다. contract lens 가 brute-force 로 원인까지
특정했다 — manifest mtime 12:14:31Z, trace mtime 12:14:49Z.

`A18-7` 도 같은 뿌리다. trace 의 `review_target_frozen`(seq 7)이 manifest 작성 이후에 쓰였고
`verify_pass`(seq 5)의 timestamp 도 manifest 보다 늦다.

### 고침 — 두 가지를 함께 한다

1. **freeze 를 마지막에 한다.** trace·evidence·문서를 다 쓴 뒤에 얼린다.
2. **`evidence-trace.jsonl` 을 target 에서 뺀다.** freeze 자체를 기록하려면 그 기록이
   freeze 뒤에 생긴다 — **자기참조다.** target 파일이 자기 자신을 목록에 안 넣는 것과 같은
   이유이고, 그 이유를 target 머리말에 적는다.

## `N18-4` 뒷부분 — aggregate 가 무엇을 보장하나

target 머리말은 `aggregate = sha256 of the N lines above` 라고만 적었다. 세 reviewer 가
그것을 **무손상 근거**로 인용했다.

**틀렸다.** aggregate 는 manifest **행 문자열**을 해싱한다. 행이 담은 hash 가 가리키는 파일이
그 뒤에 바뀌어도 행 문자열은 그대로다. 그래서 aggregate 는 **목록 자체가 안 바뀌었다**는
것만 보장한다.

실제 보장은 **행별 hash 를 다시 계산하는 재확인 script** 다. round 18 에서 그 script 가
불일치를 잡았고 aggregate 는 못 잡았다 — 같은 실행 안에서 두 결과가 갈렸다.

target 머리말에 그 구분을 적는다.

## `A18-R1` — `.pyc` 캐시가 mutation 결과를 위조한다

**round 18 의 Advisory 중 가장 무겁다.** round 17·18 이 mutation 을 blocker 판정의 근거로
삼았다.

regression lens 가 window 값을 5→12 로 훑다가 **pristine 값 `(7,7)` 에서 FAILED** 를 얻었다.
원인은 CPython 의 bytecode 무효화가 **mtime + size** 기반이라는 것이다. test 파일을 같은
크기로 1초 안에 다시 쓰면 변경이 감지되지 않고 직전 컴파일 결과가 재실행된다.

mutation 은 정확히 그 조건을 만든다 — 짧은 문자열을 바꾸고 바로 돌리고 되돌린다.

### 고침

wave 12 의 모든 mutation 을 다음 조건에서 돌렸다.

```text
export PYTHONDONTWRITEBYTECODE=1
find . -name "__pycache__" -type d -not -path "./.venv/*" -exec rm -rf {} +
```

그리고 `CURRENT_ITEM.md` 의 Stop rule 에 남겼다. **한 번 적고 끝내지 않는다** — round 17·18
의 mutation 표가 전부 그 위험 아래 있었다.

## 새 Stop rule 다섯

`CURRENT_ITEM.md` 에 넣었다.

1. freeze 는 마지막에 하고 자기 변경을 target 에 담지 않는다
2. aggregate 일치는 무손상 증거가 아니다 — 재확인 script 가 실제 보장이다
3. mutation 을 돌릴 때 `.pyc` 캐시를 막는다
4. 새 구조가 요구하는 것을 세는 **목록 자체가 덜 찰 수 있다** — 항목마다 '처리' 와 'test'
   두 칸을 둔다
5. (`T039` 에서) 세는 범위를 밝힌다

### 규칙을 만든 wave 가 그 규칙을 한 번 어겼다

첫 freeze 직후 **이 문서에 그 결과를 적으면서** target 안의 파일을 고쳤다. 재확인 script 가
바로 잡았다.

```text
rows 85 | 어긋남 1
    specs/003-slack-proposal-card/evidence/MGC-012-P5-T040.md
```

**round 18 `N18-4` 와 정확히 같은 형태다.** freeze 뒤에 target 안의 파일을 썼다.

숨기지 않고 적는다. 두 가지를 보여주기 때문이다.

1. **그 절차 결함은 고치기 쉽지 않다.** "freeze 를 마지막에" 는 freeze 자체를 기록하는 순간
   깨진다. round 18 의 wave 11 도 같은 자리에서 걸렸다.
2. **새 재확인 script 가 실제로 작동한다.** round 18 에서 aggregate 는 같은 상황을 놓쳤고
   script 만 잡았다. 여기서도 script 가 1건을 정확히 지목했다.

그래서 **이 절을 쓴 뒤에 다시 얼렸다.** 아래가 그 두 번째 freeze 의 결과이고, 이 문서는
그 시점 이후로 바뀌지 않는다.
