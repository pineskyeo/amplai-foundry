# MGC-012-P5-T028 — Make The Operator Queries Actually Read-Only

Wave 9. round 15 `C-1`(P1), `F-3`(P1), `C-2`(B-P2), `F-4`(B-P2), `C-3`(B-P2). `D-044`.

**blocker 다섯이 한 뿌리다.** `check_startup()` 이 읽기 전용이 아닌데 그것을 확인하지 않고
"조회만" 을 help 와 주석 두 곳에 썼다.

## AC-01 / AC-02 — Reproduced Before Fixing

```text
### AC-01  network filesystem
  stranded  exit=1 exc=GovernanceFilesystemError
  decision  exit=1 exc=GovernanceFilesystemError
### AC-02  worker 가 write lock 을 쥔 상태
  stranded  exit=1  5.41s  out=''
```

첫째는 `check_startup()`(`store.py:273`)이 `connect()` **밖에서** `validate()` 를 부르기
때문이다. `T024` 의 정규화는 `connect()` 안에만 있으므로 닿지 않는다.
`GovernanceFilesystemError` 는 `RuntimeError` 이지 `GovernanceStoreError` 가 아니라
(`filesystem.py:13`, `store.py:20`) 두 command 의 except tuple 에 안 걸린다.

둘째는 `_health` → `_probe_wal_write`(`store.py:405-422`)의 `BEGIN IMMEDIATE` + `UPDATE` 다.
worker 가 write transaction 을 쥐면 `busy_timeout` 을 다 쓰고 실패한다. **5.41초.**

## The Change

`_governance_worker` 에서 `check_startup()` 을 뺐다. 그 한 줄이 다섯 blocker 를 만들었다.

**무엇을 잃는가.** `check_startup()` 은 셋을 한다.

| 검사 | 조회에 필요한가 |
|---|---|
| `filesystem_guard.validate()` | 필요하다. **`connect()` 안에 같은 검증이 있고 `T024` 가 정규화했다.** 잃지 않는다 |
| `PRAGMA integrity_check` + migration verify | 전체 스캔이다. 두 조회는 `governance_ingress_commands` 와 `governance_decision_results` 만 읽고, schema 가 낡아 그 table 이 없으면 `sqlite3.OperationalError` 로 실패한다 — **조용히 틀린 답을 내지 않는다** |
| `_probe_wal_write` | 쓰기 가능 여부다. 조회에 무관하고 해롭다 |

**store 존재 확인은 손으로 한다.** `connect()` 는 없는 파일을 sqlite 가 만들어 버린다.
그냥 열면 빈 store 에 대해 `NONE` 을 내어 operator 를 속인다. `path.is_file()` 로 먼저 막고
`_fatal` 로 닫는다.

**`--json` 을 뺐다** (`C-3`). `T026` 의 `scope.exclude` 가 "새 출력 형식(JSON 등)의 계약화.
사람이 읽는 목록이면 충분하다" 로 배제한 것을 Decision 없이 가져갔고 test 로 key 집합까지
고정했다. 되돌렸다.

**`unreadable()` 을 함께 낸다.** `T027` 이 만든 조회다. 읽을 수 없는 row 는 view 로 만들 수
없어 목록에 못 들어가는데, 조용히 빠뜨리면 목록이 완전하다고 오해한다 (`F-2`).

**help 를 사실로 바꿨다.** "No governed mutation" → "These issue SELECT statements only —
no write, no lease, no transaction that contends with a running worker."

### AC-05 의 측정 방법

`sqlite3.Connection.execute` 는 immutable type 이라 patch 할 수 없다. `sqlite3.connect` 를
감싸 `set_trace_callback` 을 걸고 **실제로 실행된 SQL** 을 받는다. patch 보다 강한 관측이다 —
우회 경로로 실행된 것도 잡힌다.

`assert seen` 으로 측정 자체가 성공했는지 먼저 확인한다. 관측이 0건인데 "write 없음" 으로
읽히면 측정 실패가 통과로 둔갑한다.

### AC-08 의 강도 유지

`--json` 을 빼면서 credential 부재 test 가 text 경로만 남았다. 확인 대상은 그대로다 —
raw ActionToken, `TOK-` 접두사, signing secret 셋의 부재.

## The Exemption That Was Wrong

`T024` evidence 가 이 결함을 `T024-A1` 로 기록하면서 "`cli.py` 는 T024 의 `allowed_paths`
밖이다" 를 면제 사유로 달았다. **`cli.py` 는 `T026` 의 `allowed_paths` 안이었다.** 같은 wave
안에서 결함을 알고 적어 두고, 그 파일을 소유한 task 가 무조건 부정문으로 덮었다.

**범위 밖이라는 말은 "이 task 가 안 고친다" 이지 "아무도 안 고쳐도 된다" 가 아니다.** 면제를
적을 때 그 면제가 누구에게 적용되는지 확인한다.
