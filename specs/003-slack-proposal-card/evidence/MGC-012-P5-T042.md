# MGC-012-P5-T042 — Make the approved wording say what the code does

대상: round 19 `C19-1`(B-P2), `C19-3`(B-P2). 결정: `D-045`, `D-048`, `D-049`.

## `C19-3` — 요약 줄이 승인 범위와 반대를 말했다

`unreadable()` 의 docstring **요약 줄**이 `List every durable row that cannot be turned
into a view.` 였다. `D-048` 이 승인한 범위는 "**회수가 필요한** durable row 중 읽을 수 없는
것" 이고 `completed` 는 SQL 에서 빠진다.

본문 여덟 문단 뒤에 그 사실이 적혀 있었지만 **요약 줄은 반대를 단언했다.** round 18
`N18-2` 는 표의 **누락**을 B-P2 로 잡았는데 이쪽은 적극적 거짓 진술이다.

고친 뒤 형제 넷을 전수 대조했다.

| 함수 | 요약 줄 | 정확한가 |
|---|---|---|
| `is_unreadable()` | `Say whether this command exists but cannot be turned into a view.` | 맞다 |
| `get()` | `Return one command, or None when it is absent **or unreadable**.` | 맞다 |
| `stranded()` | `List commands no worker will claim again. Operator recovery reads this.` | 맞다 |
| `unreadable()` | `List the rows that still need recovery and cannot be turned into a view.` | **고쳤다** |

round 19 가 "어긋난 것은 이 하나" 라고 했고 대조 결과가 같다.

## `C19-1` — 승인문과 구현의 어긋남을 조용히 완화했다

`work-contract.json` 의 wave 12 AC-002 는 이렇게 요구했다.

```text
손상 row 가 leased + 만료 + attempts >= max 일 때 dead_letter 로 가면서
last_error_code 가 D-045 가 정한 INGRESS_COMMAND_UNREADABLE 을 갖는다.
```

구현은 그 상태에서 **`INGRESS_LEASE_EXPIRED`** 를 남기고 test 가 그것을 단언한다. wave 12 는
"결함이 아니라 다른 경로" 로 판단했는데, **그 판단을 `T038.yaml` 의 AC-03 으로만 적었다** —
"실제 값을 evidence 에 적고" 로 요구를 낮춘 것이다. contract 원문에는 정정도 각주도 없었고
`D-045` 에도 재해석이 없었다. 그리고 `all_acceptance_passed: true` 로 닫혔다.

**AC 를 구현 뒤에 완화한 것이고 Stop rule 이 금지하는 형태다.**

### 판단 자체는 옳다

`D-045` 의 승인문은 "`claim_next` 가 durable ingress command row 를 `IngressCommandView` 로
만들지 못하면 그 row 를 `dead_letter` 로 옮기고 `last_error_code` 에
`INGRESS_COMMAND_UNREADABLE` 을 적는다" 다. 그 문장은 **`_dead_letter_unreadable` 이 치우는
경로**를 서술한다. sweep 이 먼저 치우는 경로는 그 문장이 다루는 대상이 아니다.

`D-045` 가 **실제로 요구하는 것**은 그 row 가 operator 에게 보이는 것이고, 세 경로 모두
`unreadable()` 에 나온다 (`T041` AC-03 표).

### 처리 — 승인문은 고치지 않고 각주를 단다

`D-045` 에 `Implementation note (2026-08-26, round 19 C19-1)` 을 추가했다. round 16
`A16-1` 이 같은 형태로 각주를 단 선례가 있다.

각주가 적은 것은 셋이다.

1. `INGRESS_COMMAND_UNREADABLE` 은 `_dead_letter_unreadable` 경로의 표시이지 "읽을 수 없는
   row 는 모두 그 code 를 갖는다" 가 아니다
2. sweep 이 먼저 치우는 경로가 **둘** 있고 각각 다른 `last_error_code` 를 갖는다
3. wave 12 가 이 해석을 manifest 에만 적어서 round 19 가 어긋남으로 잡았다

**승인 문구는 고치지 않았다.** Knowledge Safety 가 삭제보다 기록을 요구한다.
