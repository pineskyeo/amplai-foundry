## The Change

`amplai-foundry governance` typer sub-app 하나와 command 둘. 기존 sub-app 패턴
(`source`, `proposal`, `curate`, `schema`, `project`, `intake`, `roadmap`)을 그대로 따른다.

| command | 답하는 것 |
|---|---|
| `governance stranded` | 어떤 command 가 다시 claim 되지 않는가 (state, attempts, `last_error_code`) |
| `governance decision <command_id>` | 그 command 의 결정이 실제로 commit 됐는가 |

둘 다 `--workspace` 를 받고 `stranded` 는 `--limit` 을 받는다.

> **정정 (round 15 `C-3`).** 처음에는 `--json` 도 넣었다. `T026` 의 `scope.exclude` 가
> "새 출력 형식(JSON 등)의 계약화. 사람이 읽는 목록이면 충분하다" 로 배제한 것이다.
> 배제를 뒤집는 Decision 없이 가져갔고 test 로 key 집합까지 고정했다. `T028` 이 뺐다.

**조회만이다.** `recovery_hold`·`dead_letter` 에서 빼내는 governed mutation 은 `D-044` 가
명시적으로 범위 밖에 뒀다.

## Correction — Round 15 `C-2` And `C-1`

**위 invariant "traceback 을 내보내지 않는다" 는 거짓이었다.**

`_governance_worker` 가 `store.check_startup()` 을 불렀다. 그것은 `connect()` **밖에서**
`filesystem_guard.validate()` 를 부르고, 거기서 나는 `GovernanceFilesystemError` 는 두
command 의 `except (GovernanceStoreError, GovernanceMigrationError, IngressError, ValueError)`
에 안 걸린다. `GovernanceFilesystemError` 는 `RuntimeError` 이지 `GovernanceStoreError` 가
아니다 (`filesystem.py:13`, `store.py:20`). network mount 위 store 에서 raw traceback 이
나갔다. 실측:

```text
stranded exit: 1 exc: GovernanceFilesystemError
decision exit: 1 exc: GovernanceFilesystemError
```

**더 나쁜 것은 같은 결함을 이 wave 가 이미 알고 있었다는 점이다.** `T024` evidence 가
`T024-A1` 로 그것을 기록하면서 "`cli.py` 는 T024 의 `allowed_paths` 밖이다" 를 면제 사유로
달았다. **`cli.py` 는 `T026` 의 `allowed_paths` 안이다.** T024 의 면제는 T026 에 적용되지
않는다. 한 wave 안에서 결함을 적어 두고, 그 파일을 소유한 task 가 무조건 부정문으로 덮었다.
evidence 만 읽으면 닫힌 것으로 보인다.

`MGC-012-P5-T028` 이 `check_startup()` 호출을 빼서 이것을 닫았다. 함께 닫힌 것이 셋 더 있다 —
쓰기 probe 의 write lock 경합(`F-3`), "조회만" 이라는 거짓 주장(`F-4`), 그리고 `scope.exclude`
가 배제한 `--json`(`C-3`).

**교훈은 면제를 적을 때 그 면제가 누구에게 적용되는지 확인하라는 것이다.** 범위 밖이라는
말은 "이 task 가 안 고친다" 이지 "아무도 안 고쳐도 된다" 가 아니다.
