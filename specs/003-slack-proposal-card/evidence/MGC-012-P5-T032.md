## The Position Is The Point

round 16 이 CLI raw traceback 을 **두 갈래**로 다시 냈다. trigger 도 원인도 다르다.

| 갈래 | trigger | 원인 |
|---|---|---|
| `FR-3` | read-only store → `PRAGMA journal_mode = WAL` | `T029` 의 `_OPEN_FAILURES` 축소 |
| `R16-1` | governance schema 아닌 파일 → `no such table` | `T028` 의 `check_startup()` 제거 |

같은 모양이 서로 다른 수정에서 나왔다. **정규화 위치가 잘못됐던 것이다.**

- `connect()` 에 전부 넣으면 → `legacy_*.py` 아홉 handler 가 `sqlite3.Error` 봉쇄를
  잃는다 (round 15 `R-1`).
- 아무것도 안 넣으면 → CLI 가 traceback 을 낸다 (round 16 `FR-3`, `R16-1`).
- **CLI 는 최종 소비자다.** 그 아래에서 아무도 class 를 구분하지 않는다. 여기가 경계다.

## AC-01 ~ AC-03 — Store States, Counted Exhaustively

reviewer 가 지목한 둘로 끝내지 않고 **일곱 상태를 전수로** 쟀다.

| 상태 | 착수 전 exit | 착수 전 raw exception |
|---|---|---|
| read-only store | 1 | `OperationalError` ← `FR-3` |
| governance schema 아님 | 1 | `OperationalError` ← `R16-1` |
| **빈 파일** | 1 | `OperationalError` ← **reviewer 가 못 본 것** |
| 디렉터리 | 1 | — |
| **손상 파일** | 1 | `DatabaseError` ← **reviewer 가 못 본 것** |
| 없는 store | 1 | — |
| 정상 | 0 | — |

**넷이다.** 둘이 아니라. `DatabaseError` 도 `sqlite3.Error` 의 subclass 라 하나로 닫힌다.

## The Change

두 command 의 except tuple 에 `sqlite3.Error` 를 더했다. 그리고 `C16-1` 의 CLI 쪽 —
읽을 수 없는 id 에 `UNKNOWN` 을 낸다. 판정은 `IngressService.is_unreadable()` 이 한다.
**CLI 가 스스로 판정하지 않는다** — 두 곳에서 판정하면 그것이 다음 형제가 된다.

`R16-1` 이 지적한 주석도 고쳤다. "조용히 틀린 답을 내지 않는다" 만 적고 traceback 이 된다는
것을 안 적었던 부분이다.
